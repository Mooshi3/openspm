# M14 native GX architectural audit — 12 September 2026

Repository tracking copy of the Astra architectural audit performed against `Mooshi3/spm-recomp`, branch `m14-native-execution`, revision `eed055a538cab8e5fac7f3ec22fc8380bfd4ed2e`, with pinned Aurora `749d6ee7a22bdfab78c8ece9047bca5d79aa72ca` plus OpenSPM's raw-GX/raster/reentrancy/guest-array/TLUT adaptations.

This document is a diagnosis and implementation plan, not runtime proof. The player Windows machine remains authoritative for compile/runtime validation. `M14-RESUME.md` contains the live checkbox state for these findings.

## Executive conclusion

There are multiple demonstrable correctness defects beyond TLUT routing. Repair the EFB copy-format decoder and MEM2 copy-address mapping first, fix raw 1024-pixel dimensions, then capture one affected SEQ_LOAD frame before choosing among SU coordinate scale, TEV liveness, display-copy/EFB lifecycle, invalidation/lifetime, and hosted display-list semantics. Separately, inspect inconsistent guest clocks before treating the slow opening story as a renderer-throughput problem.

Nothing in this audit requires abandoning the native/OpenPete-style architecture.

## Evidence already established

- Strict-native boot reaches title and SEQ_LOAD/file select with no emulator fallback.
- Native input is responsive after once-per-frame button latching.
- `./win/us/filesel.tpl` is resident and structurally valid: 170208 bytes, 32 images, MEM2 data at `0x91D931A0` in the audited run.
- Hosted display-list construction repeatedly succeeds with ordinary 96/128-byte results.
- Save select nevertheless renders as a black screen with two rows of gray segmented rectangles.
- Correcting raw TLUT size encoding and hardware TLUT-region routing did not change that image.
- The opening “Ahem! Today...” section remains very slow despite write-gather and renderer transport batching.

These facts rule out treating the TPL container or display-list producer as already-proven root causes, but they do not prove each image payload, executed list, texture binding, sampling result, TEV alpha, or EFB lifecycle is correct.

## Finding 1 — EFB copy format is reconstructed incorrectly

The installed raw raster adaptation decodes the copy format using:

```cpp
reg_get(value, 4, 3)
```

The Wii hardware field is rotated relative to the logical format. Logical bits 0–2 occupy BP bits 4–6 while logical bit 3 occupies BP bit 3. The correct reconstruction is:

```cpp
const u32 code = ((value >> 4) & 7u) | (value & 8u);
```

The audit compiled the installed decoder against synthetic public GX-format words and demonstrated incorrect results for several ordinary formats. Examples included I8 becoming IA4, IA4 becoming RGB565, IA8 being rejected, RGB565 becoming R8, RGB5A3 becoming B8, and RGBA8 becoming GB8.

This can destroy channels/alpha on EFB-derived intermediate textures while leaving simpler direct-texture startup screens intact.

### Required regression

Round-trip a synthetic EFB containing distinct R/G/B/A values through supported copy formats and depth formats. Then capture one actual SEQ_LOAD texture copy and its consumer before claiming this is the screenshot root cause.

## Finding 2 — EFB copy destination loses MEM2 identity

The raw copy destination currently used a narrower shifted address mask than raw Image3:

```text
copy destination: (value & 0x001FFFFF) << 5
Image3:           (value & 0x00FFFFFF) << 5
```

This aliases a physical MEM2 destination such as `0x11000000` to MEM1 `0x01000000`, while the later Image3 lookup still resolves `0x11000000` correctly.

Aurora records GPU copy textures by mapped destination pointer and later resolves copies through the Image3 pointer. If those identities differ, the GPU resource is missed and the fallback can sample stale/uninitialized guest RAM.

### Required regression

Preserve the full valid shifted Wii address field, then assert that EFB copy destination and later Image3 resolve to the same canonical resource for synthetic MEM1 and MEM2 cases, including cached/uncached aliases at the guest-mapper layer.

## Finding 3 — Ordinary texture sampling ignores SU coordinate scale

BP `0x30..0x3F` populates Aurora's `texCoordScales`, and uniforms carry those values, but the ordinary non-indirect texture path samples `texN_uv` directly. It does not apply the GX SU scale relative to sampled image dimensions.

Direct normalized coordinates happen to work when automatic scale/image dimensions cancel. Raw GX material paths using texel-space/manual scaling can instead clamp to an edge or repeat excessively, producing solid or segmented rectangles from otherwise-valid images.

### Required diagnostic

For an affected draw capture:

- post-texgen UV range;
- SU S/T values;
- Image0 width/height;
- wrap/filter mode;
- sampled map and texture coordinate.

A synthetic checkerboard should render identically under equivalent automatic and manual coordinate representations. Keep raw-Wii conventions separate from Aurora source-port conventions in the permanent fix.

## Finding 4 — 1024-pixel raw dimensions wrap to zero

Aurora's raw fallback width/height expressions effectively do:

```cpp
(field + 1) & 0x3FF
```

A ten-bit field of 1023 represents a logical dimension of 1024, not zero. Source-port metadata normally bypasses the helper; raw Wii Image0 writes intentionally clear those source-port overrides, so OpenSPM is exposed.

### Required regression

Decode logical dimensions 1, 1023, and 1024. Inventory all 32 file-select TPL images and relevant font textures. If no affected resource is 1024 in either axis, retain the correctness fix but demote it as the current screenshot cause.

Raw mip semantics are also incomplete because the source-port-only mip flag is not populated from raw Mode0/Mode1 state.

## Finding 5 — TEV register liveness loses alpha

The shader liveness pass tracks whole-register writes. Within a TEV stage it can mark a color destination written before analyzing alpha reads. Writing RGB does not initialize alpha.

Counterexample: initial PREV alpha is 1; a stage writes texture RGB to PREV.rgb while preserving PREV.a. Current liveness can decide PREV need not be loaded, leaving the generated shader's initial alpha at zero. Alpha compare/blending can then hide a correctly textured quad.

### Required diagnostic/permanent fix

First conservatively load all four TEV registers into uniforms. If the missing UI/final alpha recovers, implement RGB/alpha-component-aware liveness that analyzes reads against state entering the stage, then records writes separately.

Do not randomly remap TEV register numbers; the audit did not find evidence for a general register-number reversal.

## Finding 6 — Display copy, clear, completion and present are conflated

Current OpenSPM/Aurora behavior does not preserve the Wii distinction among:

- EFB display-copy event;
- copy-with-clear semantics;
- DrawDone/completion;
- host frame submission/presentation.

Display-copy BP `0x52` only sets a boolean. The clear flag is ignored there. DrawDone can end an Aurora frame regardless of display-copy state, and new recording passes default to cleared attachments. This can substitute host frame clearing for guest-command clearing and can present/clear at a different boundary than the Wii intended.

### Required fixture

- draw red;
- display-copy with clear;
- draw blue before DrawDone;

Presented output must reflect the red copy, while subsequent EFB state must reflect ordered clear then blue. Also test DrawDone with no copy between two draws; submission alone must not erase guest EFB contents.

Permanent direction: ordered EFB operations, display snapshot at copy, completion distinct from present, attachments preserved across submission-only boundaries.

## Finding 7 — FIFO transport preserves bytes but is not a complete semantic parser

The 32-byte bridge and renderer batch preserve byte order, but the backend still identifies DrawDone/token boundaries by rolling raw-byte pattern matching. The pattern can theoretically occur inside vertex/XF payload and create a false boundary.

Recursive display-list handling also needs a synthetic list containing state change → DrawDone → second state change to prove the remainder after nested completion is not lost.

`ProcessingMode::Drain` also means display lists/arrays/palettes can be read later than the CPU producer wrote them. Reuse of scratch address `0x810D8B80` is a reason to compare producer/consumer hashes, not proof of corruption.

### Required regression

Use command-aware framing rather than raw pattern scanning if a synthetic payload can trigger a false completion. Capture CALL_DL address/size/hash both when submitted and when consumed before changing lifetime behavior.

## Finding 8 — Hosted display-list construction is not semantically complete

The hosted begin/end functions redirect stores, count/pad bytes, and return, but they do not reproduce all SDK dirty-shadow flush or optional context save/restore behavior. Successful list construction therefore does not prove the live CP/BP/XF shadow state around it is correct.

### Required investigation

Observe the exact SPM SDK dirty/context fields around begin/end. Prefer keeping original recompiled non-device SDK logic and hosting only the physical FIFO redirection/count operation if practical.

## Finding 9 — Additional raw-state/cache omissions

Important follow-ups from the audit:

- texture invalidation BP `0x66` has no real raw handler;
- vertex invalidation opcode `0x48` is effectively a no-op;
- raw Image3 mapping failures degrade to null/empty texture without sufficiently specific diagnostics;
- TLUT loaded state retains guest pointers instead of stable TMEM-like contents;
- source-port object IDs are zero on raw objects, so content hashing/cache behavior differs from ordinary Aurora paths;
- copy resources can outlive/reuse guest allocation identities;
- a missing texture binds Aurora's empty 1×1 texture, so a clean log does not prove resource correctness.

Add explicit per-draw missing-resource diagnostics in bounded audit mode.

## Finding 10 — Opening-story timing likely uses inconsistent clocks

Native retrace scheduling uses host monotonic time at nominal 60 Hz. The guest CPU timebase, however, advances from translated execution charges divided by 12, and guest time-read instructions expose that execution-derived timebase.

Guest elapsed-time waits can therefore progress according to how much translated code executes rather than according to retraces or real elapsed host time. This is a strong architectural fit for visibly slow timed text/animation while input remains responsive and DrawDone activity is roughly regular.

### First required measurement

Once per host second during “Ahem”, report together:

- host elapsed delta;
- retrace delta;
- guest timebase delta converted with the boot-declared frequency;
- simulation/game update delta;
- story/text timer delta if identified;
- DrawDone count;
- actual present count;
- unique frame/state progression.

If frames/retraces advance regularly while guest seconds barely move, correct the clock contract before optimizing rendering.

Permanent timing must explicitly relate VI/retrace, guest time reads, event deadlines and fixed simulation cadence. Do not accelerate gameplay or inject arbitrary timebase jumps merely to make the sentence finish. Also measure whether `next_retrace = now_after_delivery + period` accumulates callback drift; prefer phase-preserving deadlines with bounded catch-up if needed.

Only after timing measurement should throughput profiling prioritize bbox atomics/readbacks, host vsync/backpressure, texture hashing/staging, pipeline construction, then native transport.

## Finding 11 — Patch-chain reconfigure regression

The raw TLUT size repair recognizes only the original/intermediate handler. The later routing repair replaces the whole function. On a later configure, the size repair sees neither its old nor intermediate fragment and fails.

### Required fix

Recognize and validate the exact final routed implementation as already applied, or replace the sequence with a single versioned migration. Keep unknown source drift fail-closed.

Test fresh → final, intermediate → final, final → final repeatedly.

## Concrete implementation sequence

1. Fix patch-chain idempotence.
2. Correct EFB copy-format reconstruction, MEM2 copy destinations, and raw 1024 dimensions; keep each behavior independently identifiable.
3. Add a bounded opt-in capture for one stable SEQ_LOAD frame containing draw/list hashes, effective GX state, texture/TLUT/copy/TEV/cache identities, and frame-boundary reasons.
4. On the player machine, inspect decoded texture thumbnails plus raw sampled-texture/UV/final-alpha debug views for one affected quad.
5. Promote the branch indicated by evidence: SU scale, TEV liveness, EFB lifecycle, or list/resource lifetime.
6. In the same build, measure guest-clock progress and CPU/GPU/present timing during “Ahem”; choose the performance fix from measurements.

Keep command streams, texture bytes and derived player screenshots local by default. Public regression fixtures should use synthetic geometry/checkerboards/palettes/register streams. Preserve native recompilation, the bounded renderer adapter, no emulator fallback, no Nintendo code/assets in public packages, and the 218-chunk / 32-host-target / 5-inline invariants.
