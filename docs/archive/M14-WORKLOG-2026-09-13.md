## Review fixes after Astra checkpoint

Two correctness defects were found before promotion:

1. The first `submit_for_readback()` implementation was inserted before `aurora.cpp` closed its anonymous namespace. That defines `aurora::{anonymous}::gx::raw::submit_for_readback`, not the public `aurora::gx::raw` function declared by `gx_raw.hpp`. The transform now migrates that form and inserts the implementation after the anonymous namespace closes.
2. A brief interim review fix armed EFB continuation after `gfx::begin_frame()`. That is too late: `gfx::begin_frame()` calls `begin_recording()`, which creates the first EFB pass immediately. The final transform arms continuation **before** `gfx::begin_frame()`, consumes it while that pass is created, and explicitly cancels the flag if staging acquisition fails before recording starts.

`apply_readback_boundary_patch.py` is migration-aware for the original Astra form and the brief interim form. It now validates the public namespace placement, unique declarations/state, continuation helper pair, one-shot pass modification, and arm -> begin -> cancel ordering before writing any changed source. It also supports `--check-only` for structural verification.

## Display-copy lifetime audit

The submit-only bbox split intentionally does **not** call Aurora's logical `gx::texture::end_frame()`. The pending Wii display-copy latch is not consumed by the split. The display-copy implementation retains its snapshot through a shared `gfx::TextureHandle`, so later live-EFB work cannot mutate the image selected for presentation. This makes the readback split compatible with the existing GXCopyDisp snapshot repair rather than reverting to live-EFB presentation.

## Historical experiment: blocking raw-GX first-use pipelines

Pinned Aurora's pipeline cache defines `PipelinePriority::Normal` as **`async skip draw`**. The generic `gfx::pipeline_ref(const gx::PipelineConfig&)` specialization uses that Normal priority. This means a legal original-Wii GX draw may be queued while its host WebGPU pipeline is absent and can be skipped until compilation completes.

As a diagnostic/correctness experiment, OpenSPM temporarily changed raw GX first-use lookup to `PipelinePriority::Blocking`, while leaving background cache warming asynchronous. The experiment emitted bounded `M14 GX blocking pipeline wait ... wall_us=...` records.
