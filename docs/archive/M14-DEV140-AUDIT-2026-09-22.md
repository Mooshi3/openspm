# OpenSPM dev140 audit and next gates — 2026-09-22

Audited `m14-native-execution`, initially `53b64ec7`, then integrated the newer
work through `84ff81ec`. All findings below refer to that combined state.

## Current state

The native execution/performance breakthrough is real in the recorded player
runs. dev138/dev139 sustain approximately 58–61 completed Wii frames/s in the
reported gameplay windows. dev139 proves retained-XFB lifetime and approximately
100-Hz presentation on the 99.943-Hz display, but still displays only 60 unique
poses. Its remaining motion judder is consistent with uneven frame repetition.

dev140a prepares translation-only uniform copies. dev140b encodes those copies
into offscreen targets. Neither publishes interpolated poses to the window.
Both still need the Windows player runtime gate. Successful offscreen encoding
alone does not establish that the offscreen image is correct.

The newest handoff correctly identifies that Aurora uses the SDL framebuffer
dimensions by default. Do not revive the earlier claim that rasterization is
necessarily fixed at 640x480, or start resolution work to solve temporal judder.

## Repairs in this audit

1. Scoped metadata edits to the outer `DrawCommand`; `CustomDrawCommand` has
   the same payload declaration, so a whole-header unique replacement failed.
2. Accepted the cumulative zCompLoc `m14PushDraw(dstAlpha)` initializer, which
   differs from the pristine `.dstAlpha = state.dstAlpha` fixture.
3. Located preparation at the displayed-frame finish/ImGui boundary. Readback
   segmentation has another `gfx::finish()` and must not advance replay history.
4. Taught the display-copy and readback predecessor adapters about dev140's
   inserted call/state. Their next configure previously rejected the modified
   finish fragment or attempted to duplicate the readback state declaration.
5. Canonicalized cached dev140 state, preparation functions, field declarations,
   and initializers on update. Presence of an old marker is not proof that the
   current implementation is installed.
6. Integrated upstream's move of replay metadata to the outer `DrawCommand`:
   header fields, recording API, FIFO call site and migration from both old
   inline layouts are now connected. `DrawData` stays unchanged at 128 bytes.
   A 32-bit prefix plus the indexed flag would exceed that inline payload limit.
   The earlier compact-field repair was superseded by this sidecar design.
7. Fixed dev140b's attempt to slice the source-text **dictionary** while marking
   reconstructed passes. Check the exact adjacent marker in `recording.cpp`.
8. Preserved every GX uniform consumer when forming replay decisions. A shared
   range now snaps if any consumer is unmatched, invalid, indexed, or requires
   different history. Previously a matched draw could alter an unmatched draw's
   transforms through the shared range. Unmatched ranges now contribute to
   `snapped_uniforms`; matched coverage is candidate coverage, not a safety proof.
9. Added bounded `prep_us` timing to successful-preparation log rows. Startup now
   says presentation latency is *planned*, since these proofs do not implement
   delayed visual presentation. Preserved upstream's rational display scheduler,
   compact active-matrix history and explicit replay uniform upload.
10. Repaired newer migration validation that searched generated C++ for Python
    assignment strings, and preserved readback state while canonicalizing only
    the generated replay region. Fixed the const-payload mismatch caught by
    real Aurora C++ compilation after sidecar integration.
11. Connected the existing dev140a/b migration and report-analyzer tests to the
    source-gate `main()`; defining these tests had not made the launcher run them.
    Added regressions for actual cumulative source shapes and cached migration.
12. Assigned the active PN matrix index before checking uniform bounds. Compact
    snapshots previously checked slot zero before reading a potentially higher slot.

## Next work, in order

### 1. Run the existing preparation gate

Run `M14-LLVM-INTERP-REPLAY-PREP-RUN.cmd`, play the same heavy scene and camera
route, then exit normally. No cache wipe. Run `M14-INTERP-REPORT.cmd` afterward.
Check `prep_us`, main-loop completed frames, matched/snapped ranges, indexed
and snapshot rejection counts, and arena pressure. Preserve the accepted
dev139 throughput envelope. If this consumes the remaining CPU margin, reduce
snapshot/allocation/copy costs before adding more scene draws.

After that passes, use `M14-LLVM-INTERP-REPLAY-ENCODE-RUN.cmd` to measure offscreen
encoding and rejection reasons. These two tests are deliberately visual-neutral.

### 2. Establish image correctness before publishing offscreen targets

Add an **alpha=1 identity replay** mode and compare its image with the accepted
copy-time XFB. Test a normal room, moving camera, 2D/3D flip, HUD, room transition,
and an EFB-copy effect. Capture both images from the same source frame/serial.

The current encoder walks sealed EFB passes and omits resolve/copy side effects.
It does not yet identify which pass produced the GXCopyDisp image. The final EFB
can include post-copy clears or later work; presenting that final target is not
automatically equivalent to displaying the copy-time XFB. Record the display-copy
boundary explicitly and retain the replay output at that point.

Likewise, replaying only draw passes after authoritative encoding is not a full
replay of `FramePacket.ops`: texture uploads, EFB-copy textures and encoder tasks
can change resources between passes. Identify those dependencies; retain the
correct resources or reject the affected frame. A high `encoded` count is not
evidence of equivalence. Preflight range validation should also precede every
`BeginRenderPass`, rather than rejecting after partially encoding a phase.

### 3. Own completed output images through their presentation deadlines

FramePacket retention ends when the render-worker callback returns. Staging
bytes are already unmapped there, and shared GPU arenas are reused by later
frames. Do not retain a raw packet pointer or uniform offset for a later timer
callback. Encode while resources are valid, and retain immutable completed
output textures until the presenter consumes them. Queue length must stay
bounded across minimization, resize, dropped deadlines and shutdown.

Use source serials/timestamps plus an explicit one-tick presentation delay.
The rational source-phase scheduler now handles fractional display cadence.
Production publication still needs absolute host deadlines, refresh-change
handling and backpressure without slowing simulation.

### 4. Expand transform coverage only after the above gates

Keep translation-only interpolation initially. Projection, rotation/scale and
normal matrices remain current, and indexed-matrix draws snap. Sampled geometry
identity is deliberately cheaper than a full fingerprint; it is not exact
object identity, and does not prove identity of separately staged indexed
vertex-array storage. Retain the new exact projection/active-basis discontinuity checks; add
scene-cut invalidation and stronger identity where visual evidence demands it. Do not reintroduce a second `build_uniform()`
per draw, unconditional extrapolation, or full-frame blending.

Account for cost: the current proof can execute the authoritative 60 scene
renders plus approximately 100 replay scene renders per second. That is about
160 scene renders/s, not merely the cost of presenting a 100-Hz texture. Measure
CPU encoding and GPU work separately before expanding coverage.

### 5. Keep handoffs authoritative and short

The JSON still carried dev88-era performance instructions despite the newer
frontier. This audit archives that gate and points the active gate at dev140.
Keep historical experiments as history; the top handoff and active JSON fields
must agree on the accepted baseline, next command and remaining evidence gap.
